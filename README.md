# Lightpath

A browser-based, drag-and-drop DWDM lab for building intuition about the optical physical layer, in the spirit of EVE-NG or Packet Tracer but for optics.

Drag transponders, muxponders, mux/demux, EDFAs, ROADMs and VOAs onto a bench, cable them with patch cords or fiber spans, pick an A and Z transponder, and watch Rx power, OSNR, GSNR, pre-FEC BER, Q-factor, margin, CD and DGD respond. Includes alarms (LOS, Rx LOW/HIGH, amp gain range, CD out of range), a noise budget breakdown, a power-level diagram, a hop-by-hop PM table, an OSA-style spectrum at any point along the path, a live constellation, a launch-power sweep and short physics explainers.

## Run

```sh
./build.sh
open dist/lightpath.html   # or xdg-open on Linux
```

No dependencies, no bundler. (The page asks Google Fonts for Archivo and IBM Plex Mono and falls back to system fonts offline.) Run the tests with `npm test`. Topology is saved in the browser's localStorage and can be exported/imported as JSON.

## Layout

| File | What it holds |
| --- | --- |
| `src/engine.js` | Physics (`PHY`): ASE, GN-model NLI, transceiver modes, fiber types, BER/Q math, required OSNR. Also loadable in Node (`require('./src/engine.js')`). |
| `src/model.js` | Device types, preset scenarios, input validation (`sanitize`), routing (Dijkstra over the cabled graph) and the A→Z path simulation. DOM-free, also loadable in Node. |
| `src/app.js` | Canvas, palette, inspector, results views, Learn content. |
| `test/` | Node unit tests for the engine and model (`npm test`). |
| `src/shell.html` | Markup and CSS (light and dark themes). |
| `build.sh` | Syntax-checks, then concatenates shell + engine + model + app into `dist/lightpath.html`. |

## Physics model

- **ASE:** each EDFA adds `NF · hν · G · B_ref` (B_ref = 12.5 GHz, 0.1 nm), giving the familiar `OSNR ≈ 58 + P_in − NF` per amp. NF rises when gain is run below ~14 dB.
- **Nonlinear interference:** closed-form incoherent GN model (Poggiolini), the same family of physics used by TIP's [GNPy](https://github.com/Telecominfraproject/oopt-gnpy). `P_NLI = η · P³` per span, with η depending on γ, effective length, β₂, baud rate, channel count and spacing. Successive spans add incoherently on normal uncompensated fiber, but partly coherently when the dispersion map is flat (an inline DCM, or low-dispersion NZ-DSF): the cross term fades from full at 0 accumulated ps/nm to none at about 400.
- **Transceivers:** each mode has a back-to-back SNR ceiling and an implementation penalty, tuned so required OSNR lands near real values (400ZR ≈ 23 dB, 400G ZR+ ≈ 22 dB, 100G DP-QPSK ≈ 11.6 dB). BER from Gray-coded M-QAM formulas; Q = 20·log10(√2·erfc⁻¹(2·BER)).
- **Two directions:** every service is simulated both ways (A to Z and Z to A). The service status is the worse of the two, and buttons by the status pill switch every result view to either direction. Fibers have a separate return-direction connector loss and Raman pump, and amplifiers a separate return-direction output target or gain, because an amplifier box is a booster in one direction and a preamp in the other. Blank means "same as forward". Amplifier gain range, noise figure and output limit, and DCM dispersion and loss, have return-direction fields too. A fiber can be set to carry one direction only ("Carries light"), so each direction routes separately; an arrow on the cable label shows it, and a one-way fiber with no return path takes the service down.
- **Channel plan:** the Channels tab turns the line from N identical channels into a real mix: place 10G, 100G, 200G, 400G and 800G channels anywhere on the grid, give each a power offset, pick which one is the service. Each channel is evaluated on its own with its own mode, baud rate, frequency and neighbours: pairwise nonlinear noise (self term plus a cross-channel kernel, normalised so a uniform line is unchanged), position-dependent XPM and tilt, Raman gain from its frequency, and its own Rx window. Results (Rx, GSNR, Q margin, status) per channel sit in the same table; the Spectrum tab draws each channel at its own width and height; the Mixed line scenario shows 10G beside 400G. The service channel row always equals the headline numbers. Per-span channel counts are ignored in plan mode. Each channel has its own route: "Add at" and "Drop at" can be any ROADM or transponder (blank = the service's A and Z), and the channel takes the shortest path over the cabled network between them (or, with "Via", is forced through a chosen ROADM to plan a diverse route: the legs are shortest paths and a route that would revisit a node or fiber is refused), so one plan can carry channels on different routes. Fibers carry only the channels that cross them (amplifier loading, nonlinear noise, XPM and SRS follow that load), and each channel accumulates ASE, nonlinear noise, dispersion and WSS passes only along its own route, joining at the ROADM level where it is added and taking the drop port (one WSS pass, drop structure, drop amplifier) where it leaves. A cut fiber reroutes every channel. Channels that share a stretch of the service path are simulated with it; channels on other routes get their own walk over the same link loads. Channels with no route are listed as NO PATH. The service channel always runs end to end. Wavelength assignment: a slot carries one channel per fiber (wavelength continuity, no conversion), so channels on routes with no fiber in common can share a slot, while a second channel in a slot already lit on a shared fiber is BLOCKED (the service has priority, then plan order) and does not load the line. "Assign slots" runs a first-fit assignment (service fixed, longest routes first). **Wavelength converters:** "Convert at" regenerates a channel at a ROADM into another slot (an O-E-O pair). It splits the channel into two routed halves, each in its own slot and judged at its own receiver, each starting clean at the converter (noise, dispersion and WSS passes reset); the channel's status is its worst half. **1+1 protection:** "Protect" lights a second copy on the shortest route that shares no fiber with the working one (patch cords at a single-homed transponder are shared). Both copies load their fibers and need their slot free. On a cut fiber the traffic switches to the protection route immediately, and for the service also when the working route is down by margin; the channel then runs unprotected (degraded). Channels with no protection simply restore over the remaining fibers. A converted channel is protected on each side of the converter separately. **1:N shared protection** ("Protect: 1:N shared") keeps the protection copy dark while the working route is up: it loads nothing, may share its slot with other channels' protection copies (their working routes cannot fail together, since they are lit in the same slot), is only blocked by lit channels, and has its margin predicted by simulating the failure of the first fiber of its working route; a cut lights it, and two failures at once contend for the slot. **Resilience tab:** expected outages from the planned routes: cuts per year (cut rate times route length), loss detection plus switch time for 1+1, the extra turn-up time of a dark shared route, restoration time for an unprotected channel (or the repair time if no other route exists), plus the probability that both routes are down together; reported as outage per cut, downtime per year and availability. **Transients tab:** losing a share of the channels at once (an upstream cut, a protection switch) surges the survivors by 10log10(N/survivors) at every gain-controlled amplifier, reduced to the fraction 1 - exp(-response/200 us) its control loop lets through, accumulating along the cascade, with the resulting Rx power and Q margin during the surge and the dip when the channels return; each amplifier can set its own control response. The tab also plots the receiver power through the event: every amplifier's excursion rises with the 200 µs time constant until its control loop engages and is then pulled back; the excursions line up at the receiver and add. Returning channels can be ramped up over a set time (a ramp slower than the time constant lets the loops follow and shrinks the dip). **Failures other than fiber cuts:** any device can be set to *Failed* (it passes no light: routes avoid it, so unprotected channels restore around it and protected ones switch; a service with no way round shows LOS and names the device; channels that start or end at a failed ROADM are lost) or *Degraded* (an amplifier's output falls and its noise figure rises, a laser weakens, a receiver loses SNR, a ROADM, mux, VOA or DCM adds loss). Fibers can share a risk group (a duct): cutting one cuts all of them, and 1+1 and shared protection are planned to avoid the whole group. The Resilience tab includes a failure rate per amplifier or ROADM: access ROADMs that cannot be bypassed cost the full repair time, interior devices only the switch or restoration time when another route avoids them. **Client-side protection:** a transponder or muxponder can have a spare module behind an optical switch (1 dB) or a y-cable (3.5 dB), costing that much power on the transmit and receive side; if the primary fails the spare carries the traffic (warning, no light lost) and the availability estimate uses the switch time instead of the repair time for the transponder. A transponder can also be dual-homed: cable a second patch cord to another ROADM and the 1+1 protection route is planned to avoid the access cords and the access ROADM too (single-homed transponders still share their cord). Transponder failure rate is 1.5 times the device rate. **Port and card failures:** a ROADM or passive mux can lose one add/drop port (a slot) or a whole card of 8 ports: only the channels that join or leave the line through them go dark (LOS), while the rest keep running; a failed service port is reported in the headline and a 1+1 service switches if its protection route avoids the device. The Resilience tab counts the port a channel uses at 0.25 times the device rate. **Passive OADM:** a fixed add/drop filter that serves a list of slots. Channels in those slots are dropped (or added) there at the add/drop loss, while every other slot passes straight through at the small pass-through loss: no WSS, no equalisation, no amplifier. A channel in a served slot cannot pass the filter (it is blocked, or kills the service), and a channel can only be added or dropped at an OADM in a slot it serves. Channels added there leave at the local transmitter power less the add loss, unequalised. The Passive OADM bus scenario shows two sites; the planner does not use OADMs. Not modelled: wavelength blockers and Raman pumps in the transient, shared protection of converted channels, detailed switching protocols (APS), common-mode and software failures, port failures on transponders and muxponders (a failed unit is a failed device), and partial failures of single channels.
- **Power-offset optimiser:** the Channels tab's "Optimise power offsets" searches the offsets of the non-service channels (coordinate descent, each trial a full forward simulation) for the best worst-channel Q margin, then the best average; margin-rich channels such as 10G+FEC give power up to their coherent neighbours.
- **Raman amplification:** each fiber span can carry a Raman pump (0 to 1500 mW total), pumped backward, forward or from both ends, with 1, 2 or 3 pump wavelengths. On-off gain follows pump power, effective length and fiber γ, reduced by pump depletion when the signal is strong. The gain has a spectrum (a triangular Raman gain curve against pump detuning), so channels at different frequencies get different gain; the ripple falls with more pump wavelengths and shows up in the tilt figure and in per-channel results. Double Rayleigh scattering adds noise that grows with the square of the gain, so overdriving the pump costs GSNR. Backward gain acts like a lumped amplifier late in the span (about 40% of the gain counts as OSNR benefit, 4.5 dB equivalent noise figure); forward gain acts early (better ASE, but a 7 dB noise figure from pump noise and much more nonlinearity); both ends is usually best. Alarms for depletion and for pumps above 1 W. With the **coupled-wave solver** switched on for a fiber (cable inspector, Raman model) the gain, depletion and gain spectrum come from integrating the power equations of every pump wavelength and a sample of the channels along the span instead: higher-frequency waves feed lower ones through the Raman gain curve (pump to signal, pump to pump, signal to signal), photon number is conserved, forward pumps are integrated from the start and backward ones from the end until the profiles settle. The Raman tab plots the power of channels and pumps along the span and the gain spectrum for every pumped span (with the closed-form value for comparison). The noise is still the equivalent lumped amplifier plus double Rayleigh scattering, not the distributed spontaneous scattering.
- **Demand-driven planner:** the Planner tab takes a traffic list (from, to, rate, number of channels) and routes each channel: the shortest route first, then detours through other ROADMs when a fiber is full or the estimated margin is too low (a one-amplifier-per-span GN estimate with the nonlinear noise of the channels already on each fiber, ROADM filtering and dispersion), taking the first slot free on every fiber of the route. The service keeps its slot. It reports placed, blocked and out-of-reach channels, slot and fiber utilisation, and a blocking-probability curve against offered load (random traffic between ROADM pairs, fixed seed, with and without detours). "Apply to the bench" turns the result into a channel plan so the Channels tab can simulate it in full.
- **Launch re-optimisation:** the inspector's "Launch power" setting can follow the load: each amplifier whose output target is blank sets the GN-optimal per-channel power for the span after it (`P = (A / 2η)^(1/3)`, A the amplifier noise, η the nonlinear coefficient at the channels actually lit there), per direction, and the Launch sweep tab plots Q margin against channels lit for the fixed and re-optimised line. The amplifier output limit still applies; Raman gain is not included in the optimum.
- **End-of-life allowances:** the extra loss per span (default 1.0 dB) and transceiver ageing (default 0.5 dB) behind the end-of-life margin are editable in the inspector when nothing is selected.
- **Span list import:** Export / import has a "Build a line from a span list" box. Paste `km, fiber, extra loss dB` rows (for example from an OTDR or planning sheet) and it builds TRX, mux, booster, an ILA between spans, preamp, mux and TRX, with bad rows reported.
- **10G DWDM optics:** a non-coherent mode for tunable SFP+ ZR optics in switches (NRZ, 10.3 GBd, APD receiver, no FEC, about 19 dB required OSNR). With no DSP, chromatic dispersion costs SNR gradually and the link drops past 1600 ps/nm (~95 km of SMF). Values are representative, not datasheet-exact. Try the "Switch 10G DWDM optics" scenario and stretch the span past 90 km. A "10G+FEC" variant models a host-side FEC (~10 dB required OSNR instead of ~19). A Dispersion comp. device (DCF/FBG, default -1360 ps/nm and 7 dB) brings a 120 km link back inside the tolerance (see the "Switch 10G over 120 km with a DCM" scenario). Cross-phase modulation from the channels around them adds a penalty for these optics (per span, growing with launch power and effective length, over neighbours within about 400 GHz, coherent neighbours weighing more). Each neighbour's contribution also falls with its spacing and with the fiber's dispersion, because a neighbour's intensity pattern walks off the channel as both travel: the XPM noise a direct-detection receiver sees goes as atan(2πBτ)/(2πτ) with τ = D·L<sub>eff</sub>·Δλ, so a neighbour at twice the spacing counts about half and NZ-DSF is worse than SMF (normalised to a neighbour 75 GHz away on 80 km of SMF). Representative numbers, not a full XPM model (no pattern dependence or modulation-format dependence).
- **Muxponders:** a muxponder has up to 8 client ports (10G to 800G grey optics: LR/ER, DR/FR/LR4, DR4/FR4, DR8/2xFR4) feeding one coherent line port. Each client has its own fiber and connector budget against the module's Rx window and rated reach (Rx LOW, overload and over-reach alarms), and the clients must fit the line rate. 400ZR carries a single 400GbE client; OpenZR+ modes can multiplex sub-rate clients. Client values are representative IEEE/MSA numbers, not datasheet-exact. Client ports are modelled inside the device, not as separate cabled hosts.
- **End of life:** every result also carries an end-of-life run (+1.0 dB loss per fiber span, +0.5 dB transceiver ageing). A link that passes today but fails then raises an alarm.
- **SRS tilt:** first-order Raman tilt per span (grows with total power, effective length and occupied bandwidth). Amplifier gain-tilt control (on by default) and ROADM WSSs re-flatten the band. The service channel sits mid-band, so the *worst channel* (highest frequency) Q margin is reported separately, and the Spectrum tab draws the tilt.
- **Other impairments:** CD vs DSP tolerance (hard fail), mean DGD penalty vs PMD tolerance, WSS filter-narrowing penalty per pass, Rx thermal noise and overload penalty, amplifier gain range and total-output saturation.

### Simplifications

- One direction only (A → Z). Channel load is the global setting unless a fiber span overrides it; all channels are assumed equal power, centred in the C-band (191.3–196.1 THz).
- ROADM express = 2 WSS passes; add/drop = 1 WSS pass + add/drop structure; optional integrated pre/booster amps.
- Numbers are good for trends and intuition, within a few dB of reality. This is not a planning tool.

## Ideas for next steps

- Distributed Raman noise from the solver (spontaneous scattering along the span, noise figure against gain) in place of the equivalent lumped amplifier, and temperature dependence
- Planner extensions: protected demands, converters to relieve blocking, and routing that picks the amplifier launch power per channel
- Pattern- and format-dependent XPM, and a joint optimiser for launch power per span and offsets per channel
- Per-channel transients (spectral hole burning, tilt during the event) and transients through Raman pumps and ROADM wavelength blockers
- Per-channel partial failures (a degraded port), port failures that take down several devices, and an availability-driven planner (choose protection per demand to meet a target)
